# 河南县级 NDVI 数据获取手册

目标只有一句话：**最后交给我一张 CSV —— 县 × 日期 × NDVI，不要下原始影像。**
栅格聚合（谁做都行）不落在你身上，你只要把结果给我。

---

## 一、四条路线，按省事程度排

| 路线 | 平台 | 分辨率 / 频率 | 你得做什么 | 耗时 | 推荐 |
|---|---|---|---|---|---|
| **A** | Google Earth Engine | 250m / 16 天 | 上传 CSV + 粘贴脚本 | 30–60 分钟 | ★★★★★ |
| **B** | NASA AppEEARS | 250m / 16 天 | 网页点选 + 等邮件 | 20 分钟 + 排队 | ★★★★ |
| C | 地理空间数据云 | 250m 原始 HDF | 下载几百个文件 | 半天以上 | ★★ |
| D | 资源环境科学数据中心 | 1km / 月 | 注册申请 | 1–3 天审核 | ★★（精度不够） |

优先级：**先试 A**，A 打不开（网络）就走 **B**，B 也不行再走 C。

---

## 二、路线 A：Google Earth Engine（最快）

### 1. 注册
访问 `signup.earthengine.google.com`，用 Google 账号登录，选 **Noncommercial / 科研用途**，
机构填学校名。一般几分钟到几小时通过。

### 2. 上传县界（这一步最麻烦的我已经替你做完了）
`data/raw/henan_counties_wkt.csv` —— 158 个县的边界，已转成 WKT 字符串。

在 `code.earthengine.google.com` 左侧 **Assets → NEW → CSV file upload**：
- 选 `henan_counties_wkt.csv`
- 上传向导里，**Geometry 列选 `wkt`**，编码选 **UTF-8**
- 命名 `henan_counties_wkt`
- 完成后点开 asset，复制它的 ID（形如 `projects/ee-xxxx/assets/henan_counties_wkt`）

### 3. 抓数据
新建 Script，把 `data/raw/gee_ndvi_henan.js` 全贴进去，只改顶部两行：
- `ASSET` 换成上一步的 ID
- `YEARS` 先留 `[2018, 2013]`

点 **Run**，右上角 **Tasks** 会出现任务，逐个点 **RUN**。

### 4. 下载
跑完去 Google Drive 的 `henan_ndvi` 文件夹，下载刷出来的 CSV，
放到 `data/raw/ndvi/`（自己建这个目录），然后告诉我。

### 5. 全量
两年验证没问题后，把 `YEARS` 改成 2010–2024 十五个年份，再跑一遍。

## 三、路线 B：NASA AppEEARS（不想碰代码就走这条）

1. 注册 Earthdata 账号：`urs.earthdata.nasa.gov`
2. 打开 `appeears.earthdatacloud.nasa.gov` → **Extract** → **Area Sample**
3. 上传 `data/raw/henan_county_centers.csv`（157 个县中心点，经纬度列已备好）
4. 产品选 **MOD13Q1.061**，波段勾 `250m 16 days NDVI` 和 `250m 16 days pixel reliability`
5. 时间范围 `2010-01-01` ~ `2024-12-31`
6. 提交 → 排队完成会发邮件 → 下载 CSV

这条路是"县中心点代表整县"，精度比 A 粗一点，但对生育期尺度够用。

## 四、我拿到后第一步不跑模型，先验证

只会要 **2018 和 2013 两年**，因为这两个年有明确答案：

- 2018：135 个县出现 4 月低温，南召、林州、嵩县、卢氏最重
- 2013：69 个县，最大减产 10.6%

我会做这个对照：

> 4/21—5/5 这一期，霜冻县（南召、林州、嵩县、卢氏）的 NDVI 距平
> 对比 平原无霜冻县（淮阳、郸城、鹿邑、永城）

如果霜冻县的 NDVI 明显低于常年、也明显低于平原县 → 数据可用，再要全时段。
**这一步能省掉你 13 年的下载时间。**

## 五、坑清单（照做能少走弯路）

1. **NDVI 原始是 int16**，×0.0001 才是真值。脚本里已处理。
2. **fill 值 −3000**，必须用 SummaryQA 掩膜滤掉，脚本里已处理。
3. 河南跨 **h27v05 / h28v05** 两个瓦片，GEE 自动处理；自己下 HDF 时两块都要。
4. **16 天合成**，一年 23 期，4 月只有 2 期左右；霜冻后**第一期**才反映损伤，所以时间窗要留到 5 月中。
5. 只取 **3/1—6/10**（小麦关键期），能省一大半导出量。
6. 县名：GEE 输出全称（南召县），你库里是简称（南召），我这边有归一匹配（去"县/市/区"后缀），**不用你改名**。
7. 导出 CSV 时如果报内存超限，把 `tileScale` 从 4 调到 8。

## 六、我最小需要哪些列

| 列 | 必需 | 说明 |
|---|---|---|
| `name` | 是 | 县名 |
| `image_date` | 是 | 影像日期（YYYY-MM-DD） |
| `NDVI_mean` | 是 | 县内均值 |
| `NDVI_max` | 建议 | 用于剔除异常混合像元 |
| `NDVI_count` | 建议 | 有效像元数，判断该县是否被云遮 |

有这五列，我就能算出各生育期长势距平，再跑"灾种 → 长势"。
