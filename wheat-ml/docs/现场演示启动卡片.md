# 现场演示启动卡片

> 本机实测，2026-11-19。**所有路径都相对解压目录，不写死开发机盘符。**

## 一、开场前 3 分钟（必须做）

1. 打开解压后的**交付包文件夹**，双击根目录的 **`启动小麦系统.bat`**
2. 等一个黑色控制台窗口出现，里面会依次打印：Python 路径 → 依赖检查 → 服务地址
3. **再等约 30 秒**，浏览器会自动弹出 `http://127.0.0.1:5000`
   - 开发机实测：端口在 30—50 秒之间才监听，急不来
   - 换一台机器第一次启动会更慢（依赖导入 + 模型文件加载），等 50 秒也不奇怪
   - **浏览器自己弹出来 = 真的起来了**，不用手动刷新
4. 停在首页，别再动

## 二、三条硬规矩

| 规矩 | 原因 |
|---|---|
| **不要关那个黑色控制台窗口** | 服务是前台进程，关窗即停。演示到一半关掉，全站 500 |
| **不要按 Ctrl+C** | 同上，会杀掉服务 |
| **演示前别重启电脑** | MySQL80 虽是开机自启，但服务还要重新拉起，多等 30 秒容易慌 |

## 三、如果双击 bat 没反应

按顺序试，一般到第 2 步就能解决：

1. **在解压后的 `wheat-ml` 文件夹里手动起服务**：打开这个文件夹，在地址栏输入 `cmd` 回车，然后执行
   ```
   python run.py
   ```
   （若系统提示找不到 `python`，改用 `py run.py`，或换成你机器上 Python 的完整路径）
2. 看到 `Running on http://127.0.0.1:5000` 就是起来了，再打开浏览器

如果控制台报「端口被占用」：

```powershell
# 查占用
Get-NetTCPConnection -LocalPort 5000 -State Listen
# 杀掉旧进程（把 PID 换成上一条查到的）
Stop-Process -Id <PID> -Force
```

再双击 bat。

## 四、本机已确认的三个前提（不用再担心）

| 前提 | 状态 | 依据 |
|---|---|---|
| MySQL80 服务 | **Running + 开机自启（Automatic）** | 开发机服务管理器实测 |
| MySQL 挂掉时的兜底 | **可用**：自动落本地 CSV，写入 19 行、读回 19 行、阶段统计正常 | 模拟 `available()=False` 实测 |
| 双击 bat 能起服务 | **能**，约 30 秒就绪 | 开发机实跑，HTTP 200；换机后首次可能更慢 |

### 5.1 预警演示（这一段最出效果，务必准备）

交付包另附 `豫麦智测_2026当年数据包.zip`，解压后有两份真实灾年回溯数据，直接拖进 `/upload` 即可：

| 文件 | 上传后 `/risk` 顶部应看到 |
|---|---|
| `预警演示_林州市_2018年3-4月_晚霜冻回溯.csv` | 林州市 · 拔节期 · 晚霜冻 4 天 · 04-07 最低 −3.1℃ · 重度 · 回放 |
| `预警演示_华龙区_2022年5月_干热风回溯.csv` | 华龙区 · 灌浆期 · 高温 5 天 + 干热风 2 天 · 重度 · 回放 |

讲法：先说"这两份是 2018 和 2022 的真年份，不是 2026 编的"，传完回 `/risk`，最上面那块就是系统自己判出来的险情，行尾标着「回放 · 距今 N 天」。

### 5.2 上传自愈演示（证明不只吃得下标准格式）

用 `豫麦智测_实测数据包\` 里的脏数据，三种处理各演一次：

- `反例_缺少平均气温列.csv` → 不拒收，按（最高温 + 最低温）/ 2 派生平均温，页面回报"已自动修正 1 处"
- `反例_日期与日序混用.csv` → 同时有「日期」「日序」两列，20 行数据本身能读，但系统**不猜哪个对**，直接报"日期口径混用，请只保留一种"并拦下
- `上蔡县_错误示例_缺列.csv` → 缺最低温与降水、温度列读不成数字，整份拒收，提示"看起来不是逐日气象数据"

一句话总结：能修的自己修，看不准的不猜，脏的不硬算。
