# 河南省小麦气象灾害影响分析与智能预警平台

> 副标题：基于 82 万条逐日气象观测的多源融合与县级灾害定价

## 一、项目一句话

**不问"今年能产多少"，而问"这轮灾害会把产量压低几个点、损失落在哪个县、该不该现在就投入防灾"。**

## 二、为什么是这件事

河南小麦主产区，干热风、晚霜冻、春旱、花期连阴雨年年发生。传统预警只报天气，基层拿到"明天 35℃"之后，仍然不知道：这轮灾害大概造成多大减产、要不要投入、投多少。

产量预测在这件事上帮不上忙——县与县之间本来就差一倍（信阳 300 多、豫北 500 多），模型只要"知道这个县常年多少"就能解释九成差异，真正要判断的是**今年比常年偏高还是偏低、偏离是哪种灾害造成的**。所以项目把重心从"预测产量"移到"给灾害定价"。

## 三、项目做了什么（五个环节）

1. **数据融合**：151 个县 × 15 年逐日气象 821,850 条（NASA POWER 点接口）＋ 分县产量统计年鉴标签 1,635 条（110 个有真实产量的县）＋ 县级边界 GeoJSON。
2. **灾害事件识别**：把逐日观测按五个生育期归集，自动识别 4 月霜冻、5 月干热风、高温日、低温日、暴雨日，输出"哪天、落在哪个生育期、强度多大"。这是项目最像"大数据处理"的一段。
3. **灾害定价（核心）**：双向固定效应面板回归估弹性（县固定吸收县际差异、年固定吸收年际趋势），配剂量响应曲线找阈值，再用反事实模拟算损失。只有回归验证显著的灾种才给减产量级，其余只报暴露强度。
4. **预警与决策**：按县出预警清单（灾害类型＋等级＋预估减产区间），按生育期出作业卡（依据—怎么做—不处理的后果），并留执行勾选与清空撤销。
5. **可复核**：所有结论都有导出（Excel 预警清单、县级评估报告、PDF）、有接口、有可独立运行的重算脚本。

## 四、关键数字（对外统一口径）

| 项 | 数值 |
|---|---|
| 数据规模 | 151 县 / 821,850 条逐日 / 年度特征 2,250 条 / 回归样本 1,635 条（110 县） |
| 三模型测试年 R² | LightGBM 0.9552、随机森林 0.9499、线性回归 0.9174（MAE 14.27 / 14.93 / 20.82） |
| R² 构成 | 其中 0.9063 来自"知道这个县常年产多少"，纯气象对偏离层仅 0.0371 |
| 晚霜冻（4 月） | 每多 1 天，单产相对常年下降 1.96%（95%CI −2.55%~−1.38%，p<0.001，n=1635） |
| 霜冻剂量分档 | 3—4 天 −2.58%（n=27）；≥5 天 −7.75%（n=12，唯一置信区间不跨 0） |
| 干热风/春旱/花期雨日 | p 均 >0.2，只报暴露天数，不折算减产 |
| 省级汇总回测 | 面积加权后 2022/2023/2024 偏差 −0.83% / +2.28% / −1.59%，三年合计 −0.11%（仅内部核对，页面不展示） |

## 五、技术路线为什么这么选

- **不用深度学习**：回归样本 1,635 条、15 个年份，序列模型必然更差且不可解释。样本量决定方法，这是有意识的选择，不是能力问题。
- **不接实时 API**：现场网络不可控，改用"离线增量包"——上传一份 CSV 就出结果，效果一样、风险为零。
- **不硬接 NDVI**：四天内无法完成"取数—与县年对齐—验证有效"，硬接只会得到"有图层没验证"。前置文件和对接脚本留在仓库，写进后续规划。
- **树模型降级为工具**：LightGBM 不再作为主角，只用于找候选因子、做反事实参照；统计推断全部由面板回归承担，因为需要系数、置信区间和 p 值。

## 六、已知局限（主动披露）

| 局限 | 说明 |
|---|---|
| 偏离层解释力低 | 纯气象只解释 10.1% 的县级年内波动，其余是土壤、品种、管理，数据不可得 |
| D 区系统性偏低 | 20 个低产高暴露县，MAE 18.3（是 B 区的 1.44 倍）、平均偏低 12.5 kg/亩，页面已提示"宜作下限参考" |
| 误差区间不是置信区间 | ±0.8×MAE 在测试集只覆盖 53%，页面统一称"误差量级"并标注覆盖率 |
| 年际偏移 | 2022—2024 平均偏差 +3.4/−8.6/+7.5 kg/亩，方向逐年翻转，只能靠按期重训消化 |
| 前期（播种期/越冬期） | 播种期 10 月实测不显著；越冬低温已由"全年低温日"覆盖（其中 84% 落在 12—2 月），单独拆出会被完全吸收；越冬降水与冬前积温确实显著，但跨年不可外推（加入预测模型会使测试年 R² 由 0.17 降到 −0.02），故只用于影响分析。检验见 `python -m scripts.panel_overwinter` |

## 七、怎么跑起来

双击根目录 `启动小麦系统.bat`（需 Python 3.10+ 并勾选 Add Python to PATH），浏览器自动打开 `http://127.0.0.1:5000`。首次运行自动装依赖，约 2—5 分钟。

## 八、演示建议顺序（15 分钟）

1. 首页：数据规模 + 当年灾害态势 + "当前该盯的两件事"
2. 灾害预警：110 县逐县清单，可筛选、可导出 Excel
3. 灾害地图：减产的空间差异，按年份切换
4. 农事建议：传一份当期气象 → 自动出作业卡
5. 数据诊断（上传）：传原始 CSV → 识别灾害过程 → 给减产量级
6. 产量预测：说明它现在是"已知县基线下的参照"，不是卖点
7. 稳健性（说明书附 4）：汇总回测、分象限失效、判据敏感性
