# 河南省小麦气象数据分析与产量预测系统
## 技术讲解手册（答辩用）

---

## 一、项目整体介绍

### 1.1 项目是什么
我们做了一个**小麦产量预测系统**，用河南省151个区县2010-2024年的气象数据和产量数据，训练机器学习模型，预测小麦产量，并给出农事建议和干热风预警。

### 1.2 解决什么问题
- 传统农业靠天吃饭，产量预测靠经验
- 我们用数据+AI，提前知道今年产量大概多少
- 如果减产风险大，提前预警，指导农民调整农事

### 1.3 最终效果
- 模型预测精度：R²=0.9048（融合模型，解释了约90.5%的产量变化）
- 平均误差：19.97 kg/亩（河南小麦平均亩产约400kg，误差约5%）
- 覆盖河南151个区县

## 三、数据层（最基础的部分）

### 3.1 数据从哪来
**气象数据：** NASA POWER数据库（美国航空航天局的气象卫星数据）
- 每个区县每天一条记录
- 包括：最高温、最低温、平均温、降水量、风速、辐射、湿度
- 时间范围：2010-2024年，共15年

**产量数据：** 河南省统计年鉴、各市统计年鉴
- 每个区县每年一条记录
- 包括：小麦播种面积、总产量
- 我们自己算单产（kg/亩）= 总产量 ÷ 播种面积

### 3.2 数据清洗做了什么
原始数据拿到后要先清洗：
1. **统一区县名**：比如"许昌县"现在叫"建安区"，"偃师县"改成"偃师区"
2. **单位换算**：原始数据是kg/公顷，我们转成kg/亩（÷15）
3. **缺失值处理**：有的天数据缺了，用前后天的平均值补上
4. **异常值处理**：比如某天温度50度，明显错了，删掉

### 3.3 数据库里存了什么
MySQL 数据库（wheat_ml，127.0.0.1:3306）共 4 张表，县表作为主键被其余三张表外键关联：
| 表名 | 存什么 | 多少条 |
|---|---|---|
| counties | 区县信息（县名、所属市、区域类型） | 151 个 |
| weather_daily | 逐日气象（最高/最低/平均温、降水、风速、辐射、露点、湿度） | 821,850 条 |
| feature_table | 年度 18 项生育期特征 | 2,250 条 |
| yield_labels | 建模用产量标签（真实标签，source=real） | 1,635 条 |

表间通过 county_id 外键关联 counties；天气表按「县 + 日期」、特征表和标签表按「县 + 年份」建唯一键防重复。
应用读取顺序：上传数据 → MySQL → 内置 CSV，数据库不可用时自动回退 CSV，页面功能不受影响。

## 四、特征工程（最核心的部分）

### 4.1 什么是特征？
特征就是"影响产量的因素"，我们把每天的气象数据，按小麦生育期汇总成年度指标，喂给模型。

### 4.2 小麦生育期怎么划分
河南冬小麦的生长周期：
- **返青期**：2月下旬-3月上旬（冬天睡醒了）
- **拔节期**：3月中旬-4月上旬（快速长个子）
- **抽穗扬花期**：4月中旬-5月上旬（开花授粉）
- **灌浆期**：5月中旬-5月底（麦粒灌浆）
- **成熟期**：6月上旬（收获）

我们把每天的气象数据，按这5个阶段汇总。

### 4.3 具体有哪些特征（18个）

| 特征 | 含义 | 怎么算的 |
|---|---|---|
| 生育期积温(gdd) | 整个生育期累计温度 | 每天(平均温-10℃)加起来 |
| 生育期降水 | 整个生育期总降水 | 每天降水量加起来 |
| 极端高温天数 | 超过35℃的天数 | 数一下有几天最高温≥35 |
| 极端低温天数 | 低于0℃的天数 | 数一下有几天最低温<0 |
| 干热风天数 | 高温+低湿的天数 | 高温≥35℃ 且 湿度≤40% |
| 返青期降水 | 返青阶段总降水 | 按返青期月份汇总 |
| 返青期积温 | 返青阶段累计温度 | 按返青期月份汇总 |
| 灌浆期高温天数 | 灌浆阶段高温天数 | 按灌浆期月份汇总 |
| ... | ... | ... |
| **年份序号** | 品种改良趋势 | 2010=1, 2011=2, ... 2024=15 |

### 4.4 为什么加"年份序号"？
因为小麦品种在不断改良，产量逐年提高。
加了这个特征，模型就能知道：除了气象影响，还有一个长期增产的趋势。

## 五、模型部分（最体现技术含量的）

### 5.1 用了哪几种模型
我们对比了3种模型：
| 模型 | 原理 | 精度R² |
|---|---|---|
| 线性回归 | 最简单的直线拟合 | 0.8818 |
| 随机森林 | 很多决策树投票 | 0.9048 |
| LightGBM | 梯度提升树，更快更准 | 0.9002 |

**最终采用三模型融合**：随机森林 50% + LightGBM 30% + 线性回归 20%，兼顾精度与稳健性。

### 5.2 训练/测试怎么划分的
**重要：不能随机拆分！**
- 训练集：2010-2021年的数据（12年）
- 测试集：2022、2023、2024年的数据（3年）

为什么这么分？因为预测是"用过去预测未来"，时间上不能乱。
如果随机拆分，把未来的数据拿去训练，就是"作弊"，精度虚高。

### 5.3 模型指标怎么看
- **R²=0.9048**：融合模型能解释约90.5%的产量变化，剩下约10%是其他因素（土壤、品种、管理）
- **MAE=19.97 kg/亩**：平均预测误差约20公斤
- **RMSE=27.25 kg/亩**：误差的平方平均开根号，对大误差更敏感

### 5.4 预测的原理
输入：某县某年的18个气象特征
输出：预测单产（kg/亩）

怎么算的？
模型先把每个县多年平均产量算出来（比如A县平均400kg/亩），然后根据气象条件好坏，乘一个系数（0.9-1.1之间），就是预测产量。

### 6.1 系统有哪些页面
| 页面 | 干嘛用的 |
|---|---|
| 系统概览 | 首页，看整体数据统计 |

| 产量预测 | 选区县选年份，预测产量 |
| 产量地图 | GIS地图，全省按区县着色 |
| 干热风预警 | 看哪些地方有干热风风险 |
| 农事建议 | 按生育期给出种植建议 |

### 6.2 关键功能怎么实现的

**① GIS地图**
- 用了河南省158个区县的边界GeoJSON数据
- 用ECharts画图
- 每个区县按预测产量着色，红的是减产风险，绿的是正常

**② 情景模拟**
- 预测页面有滑块，可以调积温、降水、高温天数
- 拖动滑块，实时看产量怎么变
- 比如："如果今年降水少20%，产量会降多少？"

**③ 干热风预警**
- 按生育期统计高温低湿天数
- 轻度：3-5天干热风
- 重度：≥6天干热风
- 按城市分组显示

**④ 农事建议**
- 按5个生育期分别给建议
- 结合当年气象条件：如果降水少，就提醒灌溉；如果低温多，就提醒防霜冻
- 不直接说"浇多少水"，只说方向

## 七、答辩常问问题（提前准备）

### Q1：你们为什么用随机森林？
答：我们对比了线性回归、随机森林、LightGBM三种模型；单模型里随机森林 R²=0.9048 最稳，最终用随机森林 50% + LightGBM 30% + 线性回归 20% 融合，降低单一模型波动。

### Q2：为什么不直接用平均产量？
答：平均产量只能看常年水平，我们的模型能根据当年气象条件预测，比如干旱年就自动调低，丰收年就调高，比单纯平均值准。

### Q3：数据量这么少，模型会不会过拟合？
答：我们用了按年份划分训练/测试集的方法，测试集是完全没见过的2022-2024年数据，融合模型 R²=0.9048，说明模型泛化能力没问题，不是死记硬背。

### Q4：预测错了怎么办？
答：模型平均误差20kg/亩，在农业上已经很有参考价值了。而且我们有预警线，如果预测产量比常年低5%，就触发预警，提醒农民注意。

### Q5：你们这个系统实际怎么用？
答：
1. 气象局出4-5月天气预报
2. 农民或农业部门把预报数据上传系统
3. 系统自动预测今年产量
4. 如果有减产风险，提前预警，指导农事

### Q6：创新点在哪？
答：
1. 覆盖河南151个区县，粒度细到县级
2. 不仅预测产量，还给分生育期的农事建议
3. 加了干热风预警功能
4. 做了GIS地图可视化，全省一屏看

## 八、技术亮点总结（答辩重点说）

1. **数据粒度细**：到县级，151个区县，不是笼统的全省数据
2. **特征工程专业**：按小麦生育期划分，不是随便算平均
3. **模型严谨**：按年份划分训练/测试，不作弊
4. **功能完整**：从数据上传→分析→预测→预警→建议，全链路
5. **可视化好**：GIS地图、情景模拟、分生育期建议，演示效果好
